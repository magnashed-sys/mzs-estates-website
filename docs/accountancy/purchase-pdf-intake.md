# Purchase PDF intake — staging candidate

Route: `/admin/workspaces/accountancy/purchases`. Active Group Admin only. The entire route family is restricted to Vercel preview with Supabase `senonkpxdtlhyhrubicg`. Production remains unavailable.

Select an existing entity/year administration, upload one PDF (up to 4 MiB), retain the original privately, scan it, and propose recognised invoice fields. A clean result enables original download and manual review. Confirmation atomically creates an existing expense draft, pending annual review and immutable decision with original SHA-256. Rejection retains the original and creates no expense. No payment, deduction, ledger or tax filing is inferred.

Supplier suggestions require an explicit label and exactly one matching existing relationship. Category, property and project require user selection. Only positive EUR invoices are supported. Ambiguous dates, formatted thousands, image-only PDFs and unreadable text need manual entry; there is no OCR. PDF.js text extraction runs in a child with a 192 MB V8 heap limit, 20-second timeout, 20-page/60,000-character caps, disabled evaluation/fetch and no application credentials. Native allocations are not an OS memory sandbox.

Same SHA per entity reuses its original intake; an existing intake in another year is rejected. Supplier/number duplication is checked by the existing database constraint even across years. Database confirmation validates amounts, year, dated property payer, project scope and both user confirmations. Repeat identical decisions are idempotent. Changes require separate review, not rewriting source evidence.

Annual packages mark confirmed PDF sources as retained and retain the immutable PDF ID/hash independently of editable review notes. Original PDF bytes are downloaded from the PDF register; they are not embedded in the existing year-package ZIP. The underlying legacy expense source-status column remains unchanged. No retention/deletion period or correction/reversal workflow is introduced by this candidate.

## Activation blockers

The existing Cloudmersive adapter is disabled by default. No API key or service key has been installed and no invoice has been transmitted to the provider. Before enabling real processing, confirm provider/region/privacy terms and provision the private scanner connection. The isolated preview requires:

- `MZS_OPS_AV_SCAN_ENABLED=true`
- `MZS_OPS_AV_PROCESSOR_APPROVED=true`
- `MZS_OPS_CLOUDMERSIVE_API_KEY` (private)
- `MZS_OPS_STAGING_SCANNER_SERVICE_ROLE_KEY` (private, staging project only)

Never configure these on production for this candidate. Public staging URL/key alone expose the disabled-state review UI. Browser uploads cannot create clean scan results or decisions directly. Service-role credentials cannot call the confirmation RPC. Quarantined/blocked PDFs cannot be downloaded by users. Stored downloads verify the source checksum.

After configuration: perform a synthetic real upload/scan/download/confirm/retry flow on the deployed preview, verify English/Spanish desktop and mobile using a signed-in test admin, then obtain release approval. No production migration/deployment is included here.
